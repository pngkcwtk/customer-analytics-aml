# การวิเคราะห์ข้อมูลลูกค้าเพื่อพัฒนากลยุทธ์เพิ่มยอดขายและรักษาฐานลูกค้า

Mini-project ในรายวิชา **06026211 การเรียนรู้ของเครื่องเชิงประยุกต์ (Applied Machine Learning)** ภาคเรียนที่ 1 ปีการศึกษา 2569 สาขาวิทยาการข้อมูลและการวิเคราะห์เชิงธุรกิจ คณะเทคโนโลยีสารสนเทศ สถาบันเทคโนโลยีพระจอมเกล้าเจ้าคุณทหารลาดกระบัง

โครงงานนี้ประยุกต์ใช้ Python และ Machine Learning เพื่อทำความเข้าใจพฤติกรรมการซื้อของลูกค้า ตั้งแต่การค้นหาสินค้าที่มักซื้อร่วมกัน การแบ่งกลุ่มลูกค้า ไปจนถึงการทำนายความเสี่ยงที่ลูกค้าจะหยุดซื้อ โดยดำเนินงานตามกระบวนการ **CRISP-DM** และแปลงผลการวิเคราะห์เป็นข้อเสนอแนะทางธุรกิจ

## วัตถุประสงค์และแนวทางการวิเคราะห์

| ประเด็น | คำถามทางธุรกิจ | เทคนิคที่ใช้ |
| --- | --- | --- |
| Increase Basket Size | สินค้าใดมักถูกซื้อร่วมกัน และเหมาะกับการจัดโปรโมชันร่วมกัน? | Association Rule Mining ด้วย Apriori และ FP-Growth |
| Customer Segmentation | ลูกค้ามีพฤติกรรมแตกต่างกันอย่างไร และควรดูแลแต่ละกลุ่มอย่างไร? | RFM Analysis ร่วมกับ K-Means Clustering |
| Customer Retention | ลูกค้ารายใดมีแนวโน้มจะหยุดซื้อ และมีสัญญาณเตือนอะไรบ้าง? | Logistic Regression เปรียบเทียบแบบปกติ แบบปรับน้ำหนักคลาส และแบบเพิ่ม Purchase Trend |

## กระบวนการทำงาน

1. **Business Understanding** — กำหนดปัญหา เป้าหมาย และเกณฑ์ประเมินผล
2. **Data Understanding** — สำรวจข้อมูลลูกค้า สินค้า ธุรกรรม และสถานะ churn
3. **Data Preparation** — จัดการข้อมูลซ้ำ ค่าว่าง รูปแบบข้อมูลไม่สอดคล้อง และรายการคืนสินค้า พร้อมสร้างตัวแปรสำหรับแต่ละงาน
4. **Modeling** — สร้างกฎความสัมพันธ์ แบ่งกลุ่มด้วย RFM และ K-Means และฝึกโมเดลทำนาย churn
5. **Evaluation** — ประเมินด้วย Support, Confidence, Lift, Silhouette Score และตัวชี้วัดการจำแนกประเภท
6. **Deployment** — สาธิตการแปลงผลเป็นคำแนะนำสินค้า กลยุทธ์รายกลุ่ม และลำดับความสำคัญของแคมเปญรักษาลูกค้าใน notebook

## ข้อมูลที่ใช้

Notebook อ่านข้อมูลจากไฟล์ CSV จำนวน 6 ตาราง ซึ่งเชื่อมกันผ่าน `customer_id`, `transaction_id` และ `product_id`

| ไฟล์ | รายละเอียด |
| --- | --- |
| `customers.csv` | ข้อมูลพื้นฐานและสมาชิกของลูกค้า |
| `products.csv` | ข้อมูลสินค้า หมวดหมู่ และราคา |
| `transactions.csv` | ข้อมูลธุรกรรม วันที่ซื้อ และยอดใช้จ่าย |
| `transaction_items.csv` | รายการสินค้าในแต่ละธุรกรรม |
| `support_tickets.csv` | ข้อมูลการติดต่อฝ่ายบริการลูกค้า |
| `churn_labels.csv` | สถานะการหยุดซื้อและวันที่อ้างอิง |

**ชุดข้อมูล CSV ไม่ได้รวมอยู่ใน repository นี้** ผู้ที่ต้องการรันซ้ำต้องจัดเตรียมข้อมูลต้นฉบับเอง โดยข้อมูลสำหรับ RFM มีลูกค้า 3,000 คน ส่วนการสร้างโมเดล churn ใช้ลูกค้าที่มีประวัติซื้อในช่วงสร้างตัวแปร 2,876 คน

### การแบ่งช่วงเวลาสำหรับการทำนาย churn

- กำหนด churn เป็นการไม่มีการซื้อสินค้ามากกว่า 90 วัน ณ วันที่ 31 สิงหาคม 2026
- **Feature Window:** 1 กันยายน 2024 ถึง 1 มิถุนายน 2026
- **Outcome Window:** 2 มิถุนายน 2026 ถึง 31 สิงหาคม 2026
- สร้างตัวแปรทำนายจากช่วง Feature Window และไม่นำ `recency_days` หรือ `last_purchase_date` ในตาราง label มาใช้เป็นตัวแปรทำนายโดยตรง เพื่อลดปัญหา Data Leakage
- แบ่งข้อมูลฝึกและทดสอบในสัดส่วน 80:20 โดยใช้ stratification ตามสถานะ churn และ `random_state=42`

## ผลการทดลองสำคัญ

ค่าต่อไปนี้อ้างอิงผลลัพธ์ที่บันทึกอยู่ใน notebook ไม่ใช่ผลจากการรันใหม่ใน repository นี้

### 1. การวิเคราะห์สินค้าที่ซื้อร่วมกัน

Apriori และ FP-Growth พบ Frequent Itemsets อย่างละ **410 ชุด** และกฎที่ผ่านเงื่อนไข Lift > 1 อย่างละ **96 กฎ** โดย Apriori ใช้เวลาประมาณ 23.95 วินาที และ FP-Growth ประมาณ 100.70 วินาทีในการทดลองที่บันทึกไว้ ระยะเวลาขึ้นอยู่กับสภาพแวดล้อมและชุดข้อมูล

ตัวอย่างกฎสำหรับแนะนำสินค้า: **Coffee Creamer → Coffee Filter Paper** มี Support ประมาณ 3.01%, Confidence 65.21% และ Lift 11.69 สามารถใช้เป็นแนวทางทำ Cross-selling หรือ Bundle Promotion

### 2. การแบ่งกลุ่มลูกค้า

ใช้ Recency, Frequency และ Monetary ผ่าน Log Transformation และ Standardization ก่อนจัดกลุ่มด้วย K-Means โดยเลือก **K = 4** จาก Elbow Method, Silhouette Score และความสามารถในการตีความทางธุรกิจ

| กลุ่มลูกค้า | จำนวน | แนวทางดูแล |
| --- | ---: | --- |
| High-Value / Loyal | 663 | สิทธิประโยชน์ VIP และโปรแกรมสะสมความภักดี |
| Recent / Developing | 587 | กระตุ้นการซื้อซ้ำและแนะนำสินค้าเพิ่มเติม |
| At-Risk Valuable | 887 | แคมเปญ Win-back และข้อเสนอเฉพาะบุคคล |
| Inactive / Low-Value | 863 | แคมเปญกระตุ้นการกลับมาซื้อที่มีต้นทุนต่ำ |

### 3. การทำนายความเสี่ยง churn

| แบบจำลอง | Accuracy | Precision | Recall | F1-Score | ROC-AUC | PR-AUC* |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Baseline Logistic Regression | 0.8090 | 0.7294 | 0.4161 | 0.5299 | 0.8369 | 0.6753 |
| Balanced Logistic Regression | 0.7552 | 0.5192 | 0.7248 | 0.6050 | 0.8375 | 0.6676 |
| Balanced Logistic + Purchase Trend | 0.7569 | 0.5217 | 0.7248 | 0.6067 | 0.8377 | 0.6675 |

\* Notebook รายงานค่า `average_precision_score` ภายใต้ชื่อ PR-AUC ส่วน Precision, Recall และ F1-Score เป็นค่าของกลุ่ม churn

โครงงานเลือก **Balanced Logistic Regression** สำหรับขั้นตอนสาธิตการนำไปใช้ เพราะเพิ่ม Recall ของกลุ่ม churn จาก **41.61% เป็น 72.48%** และลด False Negative จาก **87 คนเหลือ 41 คน** แม้ Precision จะลดลง ส่วนการเพิ่ม Purchase Trend ให้ผลใกล้เคียงกัน

## วิธีเปิดและรัน

### Google Colab

1. เปิด [Google Colab](https://colab.research.google.com/) แล้วเลือกเปิด notebook จาก GitHub หรืออัปโหลดไฟล์ `.ipynb`
2. เตรียม CSV ทั้ง 6 ไฟล์ไว้ใน Google Drive
3. แก้ path ในคำสั่ง `pd.read_csv(...)` ทั้ง 6 จุดให้ตรงกับตำแหน่งไฟล์ของตนเอง เนื่องจากต้นฉบับใช้ path ส่วนตัวของผู้จัดทำ
4. ติดตั้งไลบรารีที่ยังไม่มี เช่น `pip install mlxtend` และเชื่อมต่อ Google Drive ผ่านเซลล์ `drive.mount(...)`
5. รันเซลล์ตามลำดับตั้งแต่ต้นจนจบ

### Jupyter Notebook ในเครื่อง

```bash
python -m venv .venv
```

เปิดใช้งาน environment บน Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

จากนั้นติดตั้งไลบรารีและเปิด notebook:

```bash
python -m pip install -r requirements.txt

```

ก่อนรันในเครื่อง ให้ข้ามเซลล์ `from google.colab import drive` และ `drive.mount(...)` แล้วเปลี่ยน path ของ CSV ให้ชี้ไปยังข้อมูลในเครื่อง เช่น `pd.read_csv("data/customers.csv")` โดยทำเช่นเดียวกันกับอีก 5 ตาราง
